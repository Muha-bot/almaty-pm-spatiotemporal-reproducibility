# Almaty PM2.5 / PM10 spatiotemporal modelling — reproducibility package

Reproducibility package for the manuscript:

**Spatiotemporal Modelling of PM2.5 and PM10 in Almaty: Leakage-Controlled Forecasting, GIS Predictors, and Geographically Weighted Regression**

This repository is organized around scientific provenance rather than a model leaderboard. It separates the preserved A0/A1 forecasting evidence, the KGMT monitoring snapshot, the dense PM2.5 spatial/GWR branch, and the ERA5/GIS code used for the integrated workflow.

For a short, plain-language orientation to what this repository does and does not demonstrate, see `docs/COVER_NOTE_FOR_REVIEWERS.md`.

## What is included

- immutable A0/A1 metric and hyperparameter exports;
- a hash-locked KGMT-only long table with PM2.5 and PM10 hourly observations;
- 11-station KGMT and 141-station AirGradient geometry tables;
- normalized dense-network AirGradient PM2.5 hourly table used by the spatial branch;
- 133-station 80/80 GWR target/GIS dataset and OLS-vs-GWR summary;
- archived output figures supplied with the empirical spatial package, including the same-sensor representativeness and spatial-block transfer figures (Figures 6 and 7; see `docs/FIGURE_MAPPING.md` for how each figure's numbers were verified);
- AirData.kz data builder;
- strict verification scripts for the KGMT snapshot, A0/A1 archived metrics, and spatial/GWR archive;
- ERA5 download, interpolation, audit and leakage-safe forecast-origin join code;
- GIS extraction from Copernicus DEM, ESA WorldCover and a dated Geofabrik OSM snapshot;
- OLS/VIF/Moran/GWR gate code;
- deterministic spatial-block sensitivity code;
- scripts that regenerate figures from preserved numeric artifacts.

## Key results

### Temporal forecasting (independent 2025 test block, history-only model)

Validation-selected model (chosen on 2024 data only, before the 2025 test set was touched) versus the Persistence baseline:

| Target / horizon | Persistence RMSE | Selected model | Selected-model RMSE | RMSE reduction |
| ----------------- | ----------------- | -------------- | -------------------- | --------------- |
| PM2.5 +1 h  | 17.445 | Random Forest | 15.672 | 10.16% |
| PM2.5 +24 h | 27.012 | Random Forest | 22.417 | 17.01% |
| PM10 +1 h   | 21.360 | Random Forest | 19.510 | 8.66%  |
| PM10 +24 h  | 39.638 | Random Forest | 34.560 | 12.81% |

Full table with MAE and R² for both ablation blocks: `results/tables/main_results.md` (generated by `make verify`).

### Spatial model (final 80/80 cohort, 133 stations, 956 common hours)

| Metric | Global OLS | GWR |
| ------ | ---------- | --- |
| R² | 0.514 | 0.773 |
| RMSE (µg/m³) | 5.92 | 4.05 |
| AICc | 867.7 | 821.3 |
| Residual Moran's I | 0.282 | 0.101 |

This is an in-sample fit comparison on the same 133 stations, not a test of spatial prediction at unseen locations — see `docs/REPRODUCIBILITY_STATUS.md` for the exact scope of what `make verify` checks.



`data/derived/baseline/almaty_hourly_long.csv.gz` is the normalized KGMT-only table with exactly five columns:

`parameter, ts_utc, station_id, source, value_ugm3`

Audit of the exact committed bytes:

- SHA-256: `1188fc9d87ac3f0a3a947c81ec5083646f4703620e0e3db7ed48c3d90f57b8f8`
- 613,722 rows total;
- 355,450 PM2.5 rows;
- 258,272 PM10 rows;
- 11 unique KGMT stations;
- no missing cells;
- no negative or non-finite concentration values;
- no duplicate `parameter + station_id + ts_utc` keys;
- 237,783 exact synchronized PM2.5/PM10 station-hours.

This snapshot is fixed by its SHA-256 hash: anyone re-running `make verify` checks the file against this exact fingerprint, so the checked data can never silently change.

## Verification scope (read this before citing "reproducible")

`make verify` performs **internal-consistency and hash-recomputation checks**: it confirms every archived artifact matches the SHA-256 recorded when this package was assembled, and that summary tables are correctly derived from the underlying per-configuration metrics. It is not an independent, from-scratch re-derivation of the original A0/A1 training pipeline or of the raw GIS/ERA5 rasters behind the spatial predictors. `docs/REPRODUCIBILITY_STATUS.md` states, item by item, which parts are covered by from-scratch recomputation versus hash-verified archival only, and `docs/KNOWN_LIMITATIONS.md` lists the specific, unresolved gaps (e.g. no recorded training random seed, unverified raw GIS binaries) that follow from that distinction.

## What is intentionally NOT included

- the unpublished manuscript text;
- API keys or CDS credentials;
- large ERA5 NetCDF files;
- full Copernicus/WorldCover raster tiles;
- the Kazakhstan OSM `.pbf` file;
- model pickle/joblib files;
- synthetic or placeholder figures for unreported forecasting blocks (A2/A3/SHAP).

## Quick start

### 1. Create an environment

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate

pip install -r requirements-minimal.txt
```

For an exact, tested set of package versions (rather than the minimum bounds above), use `requirements-lock.txt` instead:

```bash
pip install -r requirements-lock.txt
```

### 2. Run all offline verification checks

```bash
make verify
```

This performs three independent checks:

1. A0/A1 archived metric/hyperparameter hashes and result tables;
2. the exact KGMT `almaty_hourly_long.csv.gz` snapshot;
3. the dense AirGradient/GWR archive.

To also check Figures 6 and 7 specifically, run `make verify-new-figures`.

### 3. Regenerate figures from preserved data

```bash
make figures
```

### 4. Rebuild a current AirData.kz KGMT long table

```bash
python src/data/build_almaty_hourly_long.py \
  --out data/raw/almaty_hourly_long.csv.gz \
  --qc data/raw/almaty_hourly_long_qc.json
```

The builder downloads the current version of the AirData.kz dataset and records exactly which version it used in a generated QC file. Because AirData.kz is updated over time, a later download may differ from the snapshot committed to this repository; the snapshot committed here is the one used for the manuscript's reported numbers, and should not be replaced silently.

### 5. ERA5 branch (not part of the reported forecasting results)

Primary ERA5 source: C3S/ECMWF `reanalysis-era5-single-levels`, DOI `10.24381/cds.adbb2d47`.

The ERA5 variables prepared here are temperature, relative humidity derived from temperature/dew point, surface pressure, u10, v10 and 1-hour precipitation. Meteorology is joined at the forecast-origin UTC hour; target-hour reanalysis is not permitted, to avoid leakage.

```bash
python src/era5/fetch_era5_almaty.py --help
python src/era5/process_era5_to_stations.py --help
python src/era5/join_era5_at_forecast_origin.py --help
```

Raw ERA5 files are not stored in this repository.

### 6. GIS and GWR branch

The spatial code uses:

- EPSG:32643;
- Copernicus DEM GLO-30;
- ESA WorldCover 2021 v200;
- a dated Geofabrik Kazakhstan OSM snapshot;
- the locked 80/80 AirGradient common-hour target;
- a pre-GWR missingness/correlation/VIF/OLS/residual-Moran gate;
- adaptive bi-square GWR with AICc bandwidth selection.

See `docs/README_GWR_GATE.md`.

## Scientific safeguards

- no random row split for the primary forecast claims;
- 2025 is not used for hyperparameter selection;
- lags are defined by exact elapsed time;
- KGMT and AirGradient are not treated as instrumentally interchangeable;
- large concentrations are not removed merely for being high;
- A1-A0 signs are retained even when adding cross-PM history worsens error;
- no fabricated confidence interval is calculated from aggregate hourly metrics;
- raw GIS/ERA5 source files are versioned/fingerprinted rather than silently replaced;
- missing provenance fields are labeled as unknown rather than reconstructed from memory.
