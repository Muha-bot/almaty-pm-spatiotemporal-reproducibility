# Known limitations

This file lists limitations that a reviewer flagged and that **cannot be
closed by editing this repository**, because doing so would require either
inventing information that was never recorded, or filling in identifying
details that are deliberately kept as placeholders until the authors
finalize them. Each item states exactly what is missing and what a reader
should conclude from that.

## 1. No recorded random seed for the archived A0/A1 model selections

`data/derived/baseline/selected_hyperparameters.csv` records the selected
hyperparameters (e.g. `max_depth`, `n_estimators`, `learning_rate`) for each
target/horizon/ablation combination, but **no `random_state`/`seed` field
was supplied** for the RandomForest and XGBoost entries.

Consequence: even if the original row-level A0/A1 training script were
recovered (see `REPRODUCIBILITY_STATUS.md`), re-running it with the
recorded hyperparameters would not be guaranteed to reproduce the archived
MAE/RMSE/R² values bit-for-bit, because tree/split randomness would differ
run to run. `make verify` confirms the archived *outputs* are internally
consistent and hash-locked; it does not certify seed-level retraining
reproducibility. This is disclosed here explicitly rather than silently
adding a seed value, which would misrepresent what was actually run for the
manuscript.

Where seeds **are** recorded and retraining-level reproducibility **does**
hold: the spatial-block cross-validation and Moran's I permutation test
(`src/spatial/reproduce_spatial_block_cv.py`, `KMeans(random_state=20260904,
n_init=20)`, permutation `seed=20260906`).

## 2. GIS/DEM/OSM raw source files are referenced, not hash-verified

`data/locked_public_input_manifest.csv` lists the exact URLs and product
versions used for Copernicus DEM GLO-30, ESA WorldCover 2021, and the
Geofabrik Kazakhstan OSM extract. Status legend for its `status` column:

| Status | Meaning |
|---|---|
| `URL_VERIFIED_BINARY_NOT_MATERIALIZED` | The URL/version identifier was checked to exist at manifest creation time. The binary itself was **not** downloaded into this repository and its bytes were **not** hash-locked. |
| `OFFICIAL_SOURCE_VERIFIED_BINARY_NOT_MATERIALIZED` | As above, and the source is the vendor's official distribution endpoint rather than a mirror. |

Consequence: this repository cannot prove, by itself, that a later download
of these tiles is byte-identical to what was used for the manuscript's GIS
predictors. Raw GIS rasters are intentionally not committed to Git (they
are large and license-restricted); `src/gis/build_almaty_gis_predictors_v2.py`
regenerates predictors from a fresh download, which may drift from the
original extraction if the upstream provider updates a tile. The **derived**
predictor table used for the final 133-station GWR model
(`data/derived/spatial/gwr_dataset_8080_133.csv`) is itself hash-locked and
verified by `src/spatial/verify_spatial_archive.py` — only the raw upstream
rasters behind it are unverified.

## 3. What `make verify` does and does not establish

To avoid overstating the checks: `make verify` (a) recomputes SHA-256 over
every archived artifact and confirms it matches the hash recorded when this
package was assembled, and (b) recomputes the validation-selected and
A1-minus-A0 delta tables from the archived per-configuration metrics. Both
are **internal-consistency checks** — they prove nothing was corrupted or
silently altered after packaging, and that the summary tables are correctly
derived from the underlying per-run metrics. They are not an independent,
from-scratch re-derivation of the original A0/A1 training pipeline (see
limitation 1), and they are not an independent recomputation of the raw
GIS/ERA5 predictors (see limitation 2). `REPRODUCIBILITY_STATUS.md` lists,
item by item, which parts of the pipeline are covered by from-scratch
recomputation (the KGMT snapshot checks, the spatial/GWR archive checks)
versus hash-verified archival only.

## 4. Archived GWR figures are preserved images, not regenerated by code

`figures/archived/fig_gwr_FINAL_8080_coefficients.png` and
`fig_gwr_FINAL_8080_fit.png` are the original supplied images, kept for
provenance. Unlike the files in `figures/` (produced by
`src/figures/make_verified_figures.py` from the verified numeric archive),
these two are not regenerated by any script in this repository.

## 5. Institution, journal, and DOI are still placeholders

Author names (Lazat Spankulova, Gulnar Mukhamejanova, Gulsim Sagitova) are
now filled in across `LICENSE.md`, `CITATION.cff`, and `.zenodo.json`.
`[Institution]`, `[Journal name]`, and `[repository URL]` remain as
placeholders because those were not supplied; per the confidentiality
requirements this package was prepared under, this repository does not
invent them — filling them in is the authors' own action once the
affiliation, target journal, and published repository URL are final. To
catch an accidental public release before that happens, run:

```bash
python scripts/check_no_placeholders.py
```

This script (see `scripts/check_no_placeholders.py`) fails with a non-zero
exit code and lists every remaining `[Institution]`/`[Journal name]`/
`[repository URL]` placeholder in the repository, so a release cannot
silently go out with them unfilled.

A persistent DOI (e.g. via Zenodo) also does not exist yet; a ready-to-fill
`.zenodo.json` template is provided at the repository root so the archived
GitHub Release can be deposited in one step once the author list is final.

## 7. Figure 7: archived result matches, but its generating code is missing

`data/archived/spatial_block_cv_107/spatial_block_cv_summary.csv`,
recovered on 2026-09-22, shows `XGB_coordinates` with the lowest pooled and
block-macro RMSE — this matches the manuscript. See
`docs/FIGURE_MAPPING.md` ("Figure 7") for the full account. The script
that produced this archived table was not found with it, so it is
preserved evidence (like Figures 4/5), not something this repository can
regenerate independently. A from-scratch reconstruction using only
`lon, lat` as features (`src/spatial/add_coordinate_xgboost_baseline.py`,
plus a leakage-controlled nested-CV hyperparameter search in
`src/spatial/tune_coordinate_xgboost_nested_cv.py`) did **not** reproduce
this — Linear regression won instead, both with fixed and tuned XGBoost
hyperparameters. The likely explanation is that the archived model used
additional features beyond raw coordinates (the recovered cohort file also
has `cluster_id` and `median` columns) that were not recovered alongside
it. This was not resolved by guessing and tuning until the numbers
matched, consistent with the "Scientific safeguards" in `README.md`
("Differences must not be tuned away against the test set") — it is left
as an open item for the authors: [clarify] the exact feature set used for
the archived `XGB_coordinates`/`RF_coordinates` models.

Two further single, non-tuned attempts were made on 2026-09-22 using the
extra columns present in the recovered cohort file (`median`, `cluster_id`):
adding `median` overshoots the target by a wide margin (almost certainly
target leakage, since `median` is a near-duplicate of station-level `pm25`);
adding only `cluster_id` comes closer than lon/lat alone but still misses
the archived RMSE/R². Both are recorded as obtained, with no further
searching, per the same "no tuning against the target" rule. See
`docs/FIGURE_MAPPING.md` ("Figure 7 feature-set question") for the numbers.

## 8. Figure 6: archived generating script recovered on 2026-09-22, but two parameters still do not match

`data/archived/same_sensor_representativeness_v1/`, recovered from the
earliest reproducibility package supplied for this manuscript
(`Almaty_PM25_advanced_validation.zip`), contains both the archived output
*and* its generating script (`generating_script_as_supplied.py`) — unlike
Figures 4, 5, and 7, where only the output survived. Its matched-network
MAE (6.050 µg/m³) and random-median MAE (1.821 µg/m³) match the
manuscript's reported 6.05 / 1.82 to three decimal places.

Two things about this recovered archive still do not match the manuscript
text, and are disclosed rather than quietly adjusted:
- the script draws 3,000 unconstrained random networks; the manuscript
  states 10,000 — the point estimates agree closely regardless, but the
  exact 10,000-draw run has not been located;
- the manuscript's second, geometry-constrained randomization reference
  (n=8,029 networks, median MAE 2.20) is not computed anywhere in this
  script's output — that half of Section 5.6 remains unrecovered.

See `data/archived/same_sensor_representativeness_v1/README.md` and
`docs/FIGURE_MAPPING.md` ("Figure 6") for the full numeric comparison.
Note also that `results/verified/same_sensor_representativeness/` (built
before this archive was found) is a separate reconstruction that matches
neither this archive nor the manuscript — keep citing the newly recovered
archive above, not that folder, for Figure 6.
